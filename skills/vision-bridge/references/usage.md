# Usage reference

Use `vision_analyze` with:

- `images`: one or more unchanged bridge-owned WebUI references, real local paths, or remote HTTP(S) URLs only when the plugin permits them.
- `prompt`: a specific visual question.
- `provider`: an optional configured provider id.
- `detail`: `auto`, `low`, or `high`.

Good prompts identify an output contract:

- “Transcribe the dialog title, exact error code, and every button label. Mark unreadable text.”
- “Read the x/y axes and report the values of each bar with visible units; distinguish estimates.”
- “Compare these screenshots and list only visible UI differences by region.”
- “Transcribe the code exactly, preserving punctuation and indentation; flag ambiguous glyphs.”

Keep `prompt` limited to the current question and evidence contract. Do not add generic instructions such as “be concise,” “analyze deeply,” “focus on OCR,” or the user's saved custom preference. Open Eyes composes those settings after the tool call, only for the delegated provider request. This keeps the main model's prompt focused and prevents duplicate or contradictory preference text.

Local paths resolve from the current agent session working directory. A session created while Open Eyes is enabled converts every validated browser draft into a DSH attachment reference; a session created while it is disabled stays on the native DSH path. The reference is generated by the plugin; users and models must not construct or edit it. Base64, data URIs, invented paths, API keys, and arbitrary headers are still not public tool arguments.

Changing the Enable setting never changes an existing session; create a new session to adopt the new state. Changing the default Open Eyes provider remains live and applies to the next vision call in an enabled session. Tool and Skill registration stay static so the enable switch itself does not change the model-visible system prompt or tool catalog.

Open Eyes visual preferences are also live. Visual Analysis, checked Focus Areas, and the optional Custom Supplement are appended only to the delegated vision-provider prompt for each subsequent analysis. The all-default state is an exact no-op. These settings are not durable conversation content and do not change the main model's system prompt, tool catalog, or Harness loop.

The tool description is the zero-call readiness check. `READY` names the current default provider; `INSTALLED BUT NOT CONFIGURED` means explain configuration rather than calling the tool. When the user turn contains Markdown links labelled `Attached image`, pass their unchanged targets to one focused call and use the surrounding user text as the visual question. Never expose these routing instructions in the answer.

Official package installation forms are:

```sh
dsh plugin --profile web add dsh-open-eyes
dsh plugin --profile web add ./dsh-open-eyes-0.1.1-rc.2.tgz
dsh --profile web --dump-config
```

The npm package is `dsh-open-eyes`, and the intended GitHub repository is `Hyp6666/dsh-open-eyes`. GitHub and npm accounts are independent identities.

Restart an already running Web profile after installation or upgrade so DSH rescans the package's `dsh.client` metadata, then reload the browser page.

The canonical result contains text plus provider, protocol, model, image count, normalized token usage, request id, finish reason, and a truncation flag. Treat the textual analysis as evidence and communicate material uncertainty.
